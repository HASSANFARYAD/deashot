# P0 — Critical (4 open)

### P0-1 · Shoot origin validated → ✅ FIXED

`TeamDeathmatchRoom.ts:496-519` — Server now reconstructs origin from authoritative player position (`p.x, p.y + EYE_HEIGHT, p.z`), validates direction against synced `yaw`/`pitch` via `lookVectorFromYawPitch`, and logs client origin mismatch as telemetry. Anti-cheat integration tests (spoofed aim + spoofed origin) pass.

### P0-2 · Hitscan ignores world geometry → ❌ OPEN

`TeamDeathmatchRoom.ts:604-640` — `raycastPlayerCapsule` tests only player capsules. No world AABB raycast. Cover blocks and walls remain decorative on the server. Any shot through a wall still registers damage.

**Still needs:** Shared `raycastAABB()` in `packages/sim`; server must compute `tWall` before testing players.

### P0-3 · Server simulates no world collision → ❌ OPEN

`TeamDeathmatchRoom.ts:444-452` — Server collision model is `if (p.y < 0) p.y = 0` plus `±48` x/z clamp. No AABB resolution against the 15 colliders the client runs. Players clip through every cover block server-side.

**Still needs:** Shared `resolve()` function consumed by both client `CollisionWorld` and server tick.

### P0-4 · Room tuning options are client-controlled → ✅ FIXED

`TeamDeathmatchRoom.ts:153` — Gated behind `ALLOW_TEST_ROOM_OPTIONS` (env-gated, off in production). `config.ts:49-50` enforces `!IS_PRODUCTION && process.env.ALLOW_TEST_ROOM_OPTIONS === "1"`. Auth hardening integration test confirms overrides are rejected.

### P0-5 · Auth / JWT secret → ✅ FIXED

Four sub-fixes all landed:
1. `config.ts:18-28` — `JWT_SECRET` throws in production when unset.
2. `config.ts:38-40` — `REQUIRE_AUTH` defaults on in production.
3. `api/index.ts:29` — Guest tokens have `expiresIn: "12h"`.
4. `docker-compose.yml:10,28` — Uses `${JWT_SECRET:?...}` — fails on unset.

Auth hardening test confirms: tokenless join rejected, forged token rejected, valid token accepted, client room options ignored.

### P0-6 · Lint broken → ✅ FIXED

`eslint.config.mjs` exists at repo root. CI (`ci.yml:32-33`) runs `pnpm lint` between Install and Typecheck. `pnpm lint` produces 0 errors (10 `no-explicit-any` warnings).

### P0-7 · Docker deployment does not exist → ❌ OPEN

`docker-compose.yml` still builds `./docker/api`, `./docker/game-server`, `./docker/web`. The `infra/docker/` directory is empty. Compose comments are now accurate about secrets, but the Dockerfiles themselves remain unimplemented.

### P0-8 · Game server URL hardcoded to localhost → ❌ OPEN

`GameSocket.ts:121` — `new Client("ws://localhost:2567")`. `VITE_SERVER_URL` is defined in `.env.example` and `vite-env.d.ts` but never read. Dead proxy block removed from `vite.config.ts`.

# P1 — Major (14 open)

### P1-9 · Hit/damage broadcast to everyone → ❌ OPEN

`TeamDeathmatchRoom.ts:548-564` — Both `"hit"` and `"damage"` are `broadcast()`ed to all clients with `{ except: [] }` (no-op). Every player sees every hit marker and damage flash. No `myId` guard on the client side.

### P1-10 · ADS movement desync → ❌ OPEN

Server tick (`TeamDeathmatchRoom.ts:391-433`) applies full `PLAYER_SPEED` and `PLAYER_ACCELERATION` regardless of ADS state. `aim` is not a field in `PlayerInput`. The client applies `PLAYER_AIM_SPEED_FACTOR` (0.65) but the server does not — 35% speed mismatch while aiming.

### P1-11 · Stale input replays forever → ❌ OPEN

`this.inputs` is written on every `"input"` message and cleared only in `onLeave`. No `receivedAt` timestamp. Backgrounded tabs and stalled connections keep re-applying the last input at 60 Hz.

### P1-12 · Ended rooms never reset → ❌ OPEN

`endMatch()` sets `phase = "ended"`, `onTick` returns immediately. Room is never `lock()`ed, never `disconnect()`ed, never reset. `joinOrCreate("tdm")` can match it. "Play Again" drops players into frozen rooms.

### P1-13 · Countdown does not abort when players leave → ❌ OPEN

`onLeave` deletes the player and nothing else. Countdown continues when room drops below `warmupPlayers`. Phase never downgrades from `warmup` or `in-progress` back to `waiting`.

### P1-14 · Red players stack on one spawn → ❌ OPEN

`TeamDeathmatchRoom.ts:204-205` — Spawn index uses `blueCount` for both teams:
```ts
const spawn = SPAWNS[team][blueCount % SPAWNS[team].length];
```
Red players sharing a `blueCount` value stack on the same spawn point.

### P1-15 · StrictMode ghost players → ❌ OPEN

`GameSocket.leave()` (`:223-230`) clears timers and calls `await this.room?.leave()`. But `connect()` is fire-and-forget in `Game.ts:29` (`socket.connect().catch(...)`) — if StrictMode disposes before the join completes, `room` is still `null` and the join completes after disposal, leaking a ghost.

### P1-16 · Sensitivity change remounts engine → ❌ OPEN

`GamePage.tsx:127` — `settings.sensitivity` is in the effect dependency array. Dragging the sensitivity slider disposes + recreates the entire engine, socket, and scene. `applySettings()` exists at `:97-98` but is only called at construction.

### P1-17 · Client bullet impacts land on wrong surface → ❌ OPEN

`Weapon.ts:197-246` — `raycast()` tests ground plane first and returns immediately (`:204-211`), so downward-angled shots at walls always report a floor hit. Returns first intersecting AABB in list order rather than nearest.

### P1-18 · Direction sent to server is wrong ray → ❌ OPEN

`GameEngine.ts:337-343` — Client sends `shot.origin` (muzzle world position) and `dir = normalize(hitPoint - muzzleWorld)`. Origin is from `muzzleWorld`, direction is from a different ray cast from `camera.position`. The two rays diverge, especially at close range.

### P1-19 · GPU memory leaks → ❌ OPEN

- `Effects.ts:27-106` — Every `muzzleFlash()`, `bulletImpact()`, and `tracer()` allocates new geometry + material. At 600 RPM: ~10 muzzle flashes + 10 tracers + 40 spark meshes/second. `update()` removes from scene but never calls `.dispose()` on geometry/material.
- `RemotePlayers.ts:67-88` — `add()` allocates 2 geometries + 2 materials per player; `remove()` (`:110-118`) calls `scene.remove()` without disposing them.
- `GameEngine.ts:386-397` — `dispose()` never disposes map geometries/materials. Never removes `resize` listener (added `:165`).

### P1-20 · Loose input validation / no pitch clamp → ✅ FIXED

`TeamDeathmatchRoom.ts:182-185` — Now uses `Number.isFinite` (not global `isFinite`), `normalizeAngle` on yaw, `clamp` on pitch within `±PITCH_LIMIT`. `P2-25` also fixed: `normalizeAngle` (`math/index.ts:23-29`) now uses single modulo with `Number.isFinite` guard instead of unbounded `while` loop.

### P1-21 · No rate limiting → ✅ PARTIALLY FIXED

**Fixed:**
- API: `@fastify/rate-limit` registered globally (600/min) + per-endpoint (60/min on `/auth/guest`) — `api/index.ts:128-132,142`.
- Server: `allowMessage()` budget of 120 msg/s per client — `TeamDeathmatchRoom.ts:92,264-281`.
- Profile store bounded at 10K entries with LRU eviction — `api/index.ts:51,66-73`.

**Still open:**
- Room accepts unlimited `"input"` and `"shoot"` messages *per tick* before the budget check (budget is per-second, not per-tick). Work runs for every message in the tick window.

### P1-22 · Guest usernames not validated → ✅ FIXED

`api/index.ts:80-90` — Fastify JSON schema enforces `pattern: "^[A-Za-z0-9_-]{3,16}$"`. API hardening test confirms: 5000-char and markup names rejected with 400.

### P1-23 · Dead players remain standing → ❌ OPEN

`RemotePlayers.ts:90-108` — `update()` stores `player.alive` into `entry.last` but never reads it to toggle `mesh.visible`. Dead player boxes remain upright at death position for 3 seconds. Health bar divides by hardcoded `100` (`:106`) instead of `maxHealth`.

### P1-24 · Riskiest code has no tests → ❌ OPEN

`TeamDeathmatchRoom.ts` (655 lines) has zero unit tests. `raycastPlayerCapsule`, the input→movement pipeline, phase transitions, team balancing, and spawn selection are all untested. The 12+4+4 existing unit tests cover math helpers and config sanity — not the room logic.

## Key observation

The Batch 1 fixes are solid and verifiable — every one landed with an integration test that catches regressions. The security posture is now genuinely better than what the specs claimed before.

The structural gap remains the same: **the server is the weaker simulation**. P0-2 and P0-3 are the root cause of most gameplay divergence and the highest-value remaining fix. Everything in Batch 2 flows from creating the shared collision module — it closes two P0s, enables P1-10 and P1-18, and makes P1-24 (testing) possible for the code that matters most.
